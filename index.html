How it works

Embed → route to your corpus → score options → calibrate → answer or abstain. Thresholds are fitted offline from your labeled data.

The corpus is the model.

Coming from LLMs? There is no training run. You write documents; a build step fits the rest.

REFLEX · MODELLESS — the product

Knowledge lives in documents.

  1. Build: write docs per domain, label a small slice, refit — no GPU.
  2. Serve: µs answers, or abstain when the question is off-corpus.
  3. Update: edit a doc, rebuild — bit-identical, reviewable in a PR.
LAYA · OPEN WEIGHTS — the comparison

Knowledge lives in weights.

  1. Build: someone else's training run (322M–421M parameters).
  2. Serve: one forward pass per question; always answers.
  3. Update: gather data and retrain — or prompt around it.

Where does the learning happen?

In small, deterministic, replayable fits — not a training run. Confidence calibration is a 2-parameter Platt-style solve; the two abstain thresholds are percentiles of your calibration slice; optional per-label linear heads are fitted at build time by a short fixed-order SGD. All replay bit-identically. A /feedback endpoint can refit calibration from outcomes.

Is this RAG? k-NN?

Closest cousins: nearest-centroid routing and retrieval-flavored scoring. The twist is the scorer — an LZ4 drafter treats the corpus as a compression dictionary, so "how many bytes does this option add" is a predictability signal with no learned parameters. The cosine term does most of the ranking.

When should I use which?

Modelless fits a typed answer space in a domain you can describe — routing, triage, workflow decisions. Trained models win on broad knowledge you can't author. They compose: an abstain is a signal to escalate to a model only when it's worth it.

Where does the game "grammar" live?

The arena's game heads write state and options as closed-grammar sentences so every answer decodes back to exact features. That is a convention of the game lanes, not the engine — text domains just use their documents.

Zed / any agentmkdir -p .agents/skills/reflex-integration && curl -fsSL https://reflex.gist.rs/skills/reflex-integration/SKILL.md -o .agents/skills/reflex-integration/SKILL.md
Which agents does it work with?

Claude Code reads .claude/skills/; Zed reads .agents/skills/. Any agent that takes a markdown instruction file works — it is plain instructions plus exact HTTP calls.

What does it change?

Without it, an agent asked to classify or route reaches for an LLM call. With it, the agent starts a local engine, asks typed questions, fits thresholds from your labeled data, handles abstain as a fallback — and reports measured accuracy instead of a guess.

Notes & sources

Gates, claims and where each is proven
  • Every number above the fold (TL;DR, chart, G1 badge) is computed in your browser from data/bench.json, which is generated by the open harness — never hand-typed. publish_bench.py
  • G1 calibration — the fitted confidence must beat both the raw readout and the conformal-naive floor. It is not an accuracy gate; suites whose calibration window is too thin make no claim. per-suite verdicts Angelopoulos & Bates, conformal prediction (2021)
  • G2 latency (p99 per decision set) and G4 zero allocations on the hot path are GOAT-gated in the engine repo. decision_set_goat.rs gate table
  • G5 laya parity — our Rust port must match the reference checkpoints' top-1 answers (≥ 99.9%) within 1e-3 probability drift. laya_riir_parity.rs
  • laya weights are never redistributed. The optional comparison lane loads Apache-2.0 checkpoints (ModernBERT, mmBERT, mask-scoring head) from Hugging Face at runtime, SHA-256-verified; their license ships in every release's THIRD_PARTY_LICENSES.md. brainfunctioncollapse laya
  • Privacy: the engine listens on 127.0.0.1:7331, accepts one allowed browser origin, and sends no telemetry.
  • The skill-section pattern is borrowed with thanks from the laya page; the file itself is written fresh against Reflex.
